# RU: real saved inputs prepared without provider transmission

Date: 2026-09-22. Method: `saved_source_real_usage_offline_v1`.
This [pre-registered preparation](prereg-2026-09-22-real-source-usage-offline.md)
produced a private development candidate and four successful intercepted
receipt/usage rehearsals. It did **not** run Qwen on the real inputs, complete
reference blind judging or activate a public Tool Calling route.

## Data and binding

Current-disk inventory found 29 success/live benchmark directories and one
success/fixture directory. The two preselected first repetitions had consistent
live metadata/source-topic declarations and complete 19/23-entry catalogs.
All 42 saved source records were preserved, including their original ordering,
dates, titles and saved text. No source was retrieved, filtered or rewritten.
Original report/metadata/source bytes were unchanged after the local rehearsal.

The private inputs keep four ordered questions, previously chosen assisted
keywords, AI-authored candidate reference sets and independently specified
script actions separate. One reference is set-valued; the negative control
concerns absence of a fitting title in a small catalog, not absence of research.
Blind-review input is prepared with only questions and full ID/title catalogs.
Its review state remains `not_run`; no reviewer judgment has been invented.

The packet binds original bytes, derived sandbox aliases, snapshots/catalogs,
configuration, labels/scripts and working-code identity. HEAD is context, not
proof of a clean historical checkout. A different revision requires a newly
validated packet identity; it does not retroactively validate an older copy.
Raw material, detailed results, previews and private hashes are not published
here. The old RS/RQ packets and paid allowances are unchanged.

These are new questions on consumed historical evidence, not unseen samples,
human gold, source-truth verification or observations of actual user benefit.

## Intercepted usage delivery

Each of the four scripted cases traversed the current accounted Qwen wrapper,
the isolated usage app, the real controller/store and POST/GET serialization.
There were four intercepted native-HTTP entries, four temporary admission
reservations and **zero external provider calls**. GET added no selector entry,
native request or daily admission. Original and replay result/accounting content
matched; original execution and subsequent delivery-read counters remained
distinct. All network guard failure lists were empty.

Complete preview bodies matched the actual intercepted request bytes. Sizes
were 4,302 / 4,236 / 4,967 / 4,949 bytes, each below the unchanged 12,288-byte
limit. The dynamic would-send data was question plus visible source IDs/titles,
not source excerpts, report prose, labels, original metadata or capabilities.
These previews remain local and are not permission to transmit them.

Responses and their token counts were scripted. Their `reported_complete`
projections and estimated amounts validate the accounting path only; they are
not real model use, actual spend or provider invoices. A mechanical replay pass
does not establish model selection accuracy or semantic support. The four-case
dataset rehearsal is separate from the synthetic regression-test denominator.

## Regression evidence and limits

The complete offline suite passed **6,741 tests and 1,597 subtests**, compared
with the 6,677/1,592 starting baseline. Current Ruff and narrow Pylint passed.
All six existing Chromium zero-provider journeys passed afterward; no shared
browser/runtime code was changed by this preparation.
The 64 new synthetic test cases include raw binding drift, label isolation,
capacity, intercepted wire comparison, receipt replay and external-call guards.

Independent review found a test-harness gap: a swallowed guard exception during
the last GET or client exit could leave the batch marked passed. Seven new
pre-fix regressions reproduced it. Per-case exit checks, final aggregation and
parent-process consistency checks now keep that failure visible. Independent
static re-review found no remaining actionable issue in the reviewed scope.

Three deliberately reintroduced defects—ignoring aggregate guard failures,
skipping binding validation and skipping exact wire comparison—caused 1/3/1
unchanged assertions to fail. All were restored to matching source hashes.
A separate initial child-process warning-filter mismatch was corrected using
the project's existing specific TestClient filter, not a general network-warning
ignore. These are engineering fault controls, not production incidents.

The reviewer inspected code and assertions but did not run tests or inspect
private data. Execution observations above were collected by the parent task.
Runtime interception is not a hard sandbox against malicious trusted Python,
and file hashes are not attestations of historical authenticity or provider use.

## What remains

### CI diagnostic follow-up

The first PR run on `181c19f` did not pass the complete matrix:
[Windows Python 3.11](https://github.com/shuxiachai/academic-commercialization-agent/actions/runs/35687852167/job/106618418018)
failed the existing loader-time code-revocation test because its five-second
entry event was not observed. The other three Python cells, including measured
coverage, passed; the aggregate coverage gate correctly failed with the matrix.
The failed assertion did not record whether the POST was pending, rejected or
exceptional. Its exact cause was not reproduced or established locally.

A test-only diagnostic follow-up retains that five-second bound, the outer
ten-second bound and all revoked-code/zero-callback/zero-admission assertions.
It records the synthetic POST outcome on an entry miss and settles its waiter
while lifespan still owns the actual worker drain. Four negative controls cover
early HTTP rejection, an exception, cancellation and a pending POST. Reinjecting
the old event-only diagnostic makes all four unchanged controls fail.
This improves failure evidence; it is not a proven fix for the original CI
failure, and later passing runs must not erase that unresolved observation.

After this diagnostic change, complete local Python 3.11 and 3.12 runs each
passed 6,745 tests and 1,601 subtests with the same assertions and warning policy.
The temporary 3.11 installation first produced unrelated import/guard failures:
dependencies had been placed under protected outputs, and its locale-decoded
editable path did not resolve this Unicode workspace. A separate ignored venv
and a local ASCII-escaped editable path corrected that setup without changing
project guards. These local setup failures are not the original CI failure.
Independent static review found no actionable diagnostic code/document issue;
the subsequent PR matrix must still pass before release.
