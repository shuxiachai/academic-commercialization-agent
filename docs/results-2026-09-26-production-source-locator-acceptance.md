## Scope and identity

On 2026-09-26, the deployed source revision was
`3675e8e624c94e066544459817fb7762b0501502`. Its existing main CI was green.
This was a new one-attempt acceptance of the production wrapper, not a retry
of the closed [origin-rejected pilot](results-2026-09-23-source-locator-public-origin.md)
or a reopening of any isolated development batch.

The preflight bound one existing code-owned report, one question, its saved
registry identity and an expected source before dispatch. It allowed one

report prose, saved excerpts, private run metadata and labels were excluded.

semantic judging were allowed. Private artifacts remain outside this repository.

USD 0.02 reservation cap and an 86400-second minimum interval. This was a
global window, not a per-user allowance. Reservation admission is not a hard
provider invoice cap. The public-origin pin, owner-only billing, consent and
existing shared paid admission stayed in effect.

## Closure and receipt lookup across deployment

After the terminal result, new execution was disabled and both feature daily
caps were set to zero. The replacement deployment succeeded at the same source
revision and the temporarily enabled deployment was removed. Health was `ok`,
readiness was true and active paid operations were zero. The wrapper exposure
and explicit public-origin pin were retained for receipt-only observation.

Reloading the browser did not dispatch another POST or automatically fetch a
receipt, and the access-code field was cleared. After explicit authentication,
one manual same-receipt GET returned HTTP 200. Its actual response text matched
both the existing saved text and the original page delivery. Receipt identity
and accounting were unchanged. The GET recorded a delivery-snapshot read and
a delivery-source read, not a new model selection or paid operation. The
observed browser totals remained one POST and one GET.

## Evidence limits

The browser automation observer could not independently retrieve the original
POST response body. The application itself successfully decoded and rendered
the result; its DOM receipt fields, accounting and exact saved text were
retained. The subsequent GET body was captured from a clone of the actual
response before normal client consumption, without altering or mocking it.
Thus this is not a complete independent original-POST packet capture. An
independent read-only review recomputed the retained text/accounting comparison;
it was not another provider run or semantic review.

This is one prepared production delivery and post-deployment receipt lookup,
not an unseen accuracy sample, a deliberately lost-ack/crash/cancellation test,
scientific entailment verification, a provider exactly-once guarantee or proof
of user benefit. It does not establish superiority over the free Sources
keyword lookup. The earlier production-origin failure remains a separate
failure; its repair and this success are not combined into an accuracy rate.

The batch and allowance are closed. Paid execution remains disabled with zero
feature budgets. Supplementary retrieval stays zero-call shadow mode, generated
evidence answers stay experimental, and no permanent paid enablement follows
from this acceptance or its documentation merge.
