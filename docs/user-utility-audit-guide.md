# Small-panel user-utility audit guide

This guide operationalizes the protocol frozen in
[`prereg-2026-08-22-user-utility-audit.md`](prereg-2026-08-22-user-utility-audit.md).
It does not change the pre-registered estimand or thresholds.

## The sample is ten report pairs, not ten reviewers

Use **three to five independent reviewers**. Round 1 assigns each of the ten
benchmark topics exactly once across the panel:

| Confirmed reviewers | Round-1 load | Approximate burden |
|---:|---|---|
| 3 | 4 / 3 / 3 pairs | highest; usually several hours each |
| 4 | 3 / 3 / 2 / 2 pairs | moderate |
| 5 | 2 pairs each | preferred when recruitment permits |

Round 2 is optional replication. It assigns every topic once more to a
different reviewer. Never use Round 2 to replace, repair, or selectively add
to an unfavourable Round-1 result.

The reports are long: a pair contains roughly 7,000–10,000 English words. Set
expectations honestly. A willing industry proxy who completes two pairs
carefully is more useful than a nominal expert who rushes ten.

## Who can review

Prioritize, in order:

1. technology-transfer or research-commercialization staff;
2. industry research, consulting, product-strategy, or investment personnel;
3. founders, senior researchers, or doctoral researchers who have evaluated
   commercialization decisions;
4. technical proxies who can follow the decision rubric but are not target
   users.

The profile form records the role and experience instead of pretending all
reviewers have equal domain authority. At least three eligible reviewers are
required for the primary pre-registered criterion. A smaller return remains a
pilot and must not be described as a completed user study.

## Choose exactly one generated option

The generated local artifacts are intentionally ignored by Git:

```text
outputs/user-utility-audit/20260822-options/
  for-3-reviewers/
  for-4-reviewers/
  for-5-reviewers/

outputs/user-utility-audit/20260822-private/
  for-3-reviewers-answer-key.json
  for-4-reviewers-answer-key.json
  for-5-reviewers-answer-key.json
```

Wait until the final reviewer count is known, then use only the matching
option. Do not combine rows or ZIP files from different options: the random
A/B identities and reviewer assignments differ.

Each option contains ready-to-send files under:

```text
delivery/round-1/R01.zip
delivery/round-1/R02.zip
...
delivery/round-2/R01.zip
```

Keep the entire `20260822-private` directory closed until all forms included
in an analysis are returned and locked.

## Message to send a reviewer

The following Chinese message is intentionally candid about workload and the
use of the result:

> 你好，我在做一个科研成果商业化评估系统，希望验证报告是否真的能帮助人做
> go / no-go / defer 判断，而不只是验证程序能运行。想邀请你做一次匿名 A/B
> 盲评。你会收到 2–4 组同主题报告，每组先记录初始判断，再依次阅读 A、B 并
> 填一行表格。单组报告较长，预计约 30–60 分钟；如果时间不合适可以直接拒绝。
> 这不是对你专业水平的考试，也没有标准答案。请独立完成，不讨论 A/B 来源，
> 不用生成式 AI 代替实质判断；没有打开引用时按“未检查”填写即可。结果只按
> 评审编号汇总，我不会把你的姓名写入公开材料。你愿意参加吗？

Do not promise that the task takes only a few minutes. Do not tell reviewers
which version is expected to win, that one side is a multi-agent output, or
the pre-registered pass threshold.

## Collection procedure

1. Assign stable reviewer IDs (`R01`, `R02`, and so on) before sending files.
2. Send only the matching `delivery/round-1/<reviewer_id>.zip`.
3. Ask the reviewer to complete `reviewer_profile.csv` and every assigned row
   in `review_form.csv`. They must not edit `A.md` or `B.md`.
4. Lock returned Round-1 forms before sending any Round-2 packet. Do not reveal
   identities or interim aggregate results.
5. Round 2 is optional. Send only the same reviewer's matching Round-2 ZIP.
6. Copy returned CSV values into the canonical option directory while
   preserving reviewer ID, case ID, topic, and report files.
7. Archive withdrawals as blank rows. Never convert a blank to `TIE`.

Substantive judgments generated by AI are retained in the audit trail but
excluded from the main human result. Translation or clerical AI use must be
declared in the profile. Citation claims are similarly explicit: when no
source was opened, citation trust and factual errors must be `NOT_CHECKED`, not
zero.

## Validate and summarize

Replace `N` with the one chosen reviewer count and choose a new output path;
summaries are immutable by design:

```bash
uv run python user_utility_audit.py summarize \
  outputs/user-utility-audit/20260822-options/for-N-reviewers \
  outputs/user-utility-audit/20260822-private/for-N-reviewers-answer-key.json \
  outputs/user-utility-audit/20260822-private/final-for-N-reviewers.json
```

The command verifies the assignment topology and hashes of every blinded
report before reading responses. It distinguishes `not_started`, `incomplete`,
`incomplete_profile`, `ai_excluded`, `pilot_only`, and `complete` states.

## Claim boundary

This audit compares the production six-stage report with a one-node report
over identical frozen evidence. Even a passing result does **not** establish
adoption, ROI, objectively correct investment decisions, or superiority to
ordinary ChatGPT. Until eligible forms are returned, the evidence count is
zero and no user-utility result exists.
