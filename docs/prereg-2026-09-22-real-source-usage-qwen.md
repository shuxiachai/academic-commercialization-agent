# RUQ: isolated real saved-source selection and usage pilot

Registered on 2026-09-22 before any native RUQ request. This protocol prepares
a separate fixed batch; it is not permission to execute it. The implementation,
current commit, original packet bytes and independent review bundle must be
verified and separately authorized before a real provider key is read.

## Question and reference scope

The [RU offline preparation](prereg-2026-09-22-real-source-usage-offline.md)
preserves two complete historical registries, 42 source records and four new
title-location questions. The new native observation will ask whether the
current one-shot locator selects a reviewed reading candidate and delivers its
saved result and native accounting through the isolated HTTP receipt boundary.
It does not ask the model to answer a research question or judge a claim.

Use RU01-RU04 in their existing order and D1/D1/D2/D2 assignments. Do not remove
hard cases, rewrite questions, filter the catalog, change source order, add
abstracts or obtain new evidence. These are development questions over consumed
historical reports, not unseen data or a calibrated accuracy sample.

A fresh LLM judging context receives only the frozen rubric, questions and
complete ID/title catalogs. Proposed references, scripts, assisted keywords,
baseline results and saved text remain hidden on that first pass. Preserve the
actual raw judgment and its model/role provenance in a private sidecar. Effective
backend metadata may be unavailable; configuration is not model attestation.
This is AI-generated title-location reference review, not human gold, verified
article type, full-text entailment or scientific source truth.

Positive references are sets: any reviewed member may match, without forcing
a unique answer. An empty set requires the locator's explicit catalog-level
decline. A refusal, unavailable result or failed review is not a successful
no-fit. Unresolved references stop preparation rather than shrinking the batch.
Keep both the original draft and the independent judgment, including disagreement
and limitations. Original RU fields and historical `not_run` observations are
not rewritten when a later sidecar records review.

## Immutable origin and current execution identity

Bind the exact original packet file bytes separately from its internal hash.
The old RU validator remains unchanged: its full current-HEAD comparison may
reject the historical packet after a new commit. The new runner must not disable
that check or monkeypatch identity to make the old packet appear current.

Instead, rebuild from the bounded original raw inputs with the existing builder
and validate that new in-memory packet. Require the complete old working-file
hash map to equal the new one. In a comparison copy only, restore the original
code identity and recompute the packet's original internal hash; its canonical
bytes must then equal the original file exactly. The only admitted historical
identity difference is HEAD. Any changed bound dependency or altered raw,
prepared, reference, script, configuration or state bytes stops the bridge.

The new execution separately binds its exact committed code, actual import and
runtime dependency closure, dependency versions, protocol and tests. Include
the native locator, accounted selector, usage app/controller/stores and relevant
delivery assets, not merely the old RU identity list. No old identity list or
consumed batch is updated to accommodate the successor.

The independent review bundle binds its original packet, exact blind-view bytes,
rubric/submitted-prompt identity, raw judgment and provenance. The review view
must match the validated questions and complete catalogs. A self-declared review
status or hash alone is not authority to substitute different content.

## Data boundary and default behavior

Default CLI operation is identity-only: no credential lookup, provider request,
selector/app/store construction, paid admission or execution-output creation.
Use fixed local input and output locations; no arbitrary endpoint, model,
callback, retry, output-directory or fixture override is offered.

Only the exact question and visible source IDs/titles may appear as dynamic
provider prompt content. Raw report prose, saved excerpts, original metadata,
reference labels, scripts, keyword queries, run capabilities and credentials
must not enter the prompt. The full request body must match the admitted preview
bytes. Existing catalog, callback and HTTP limits remain unchanged.

This round builds and tests the runner with synthetic inputs and fake-key HTTP
interception only. The earlier RS/RQ/SLQ/SLCQ permissions, keys and output batches
remain closed. A future native grant must cover the new commit and exact private
packet/review identities, all visible titles and the batch cost boundary.
Credentials, if authorized later, are explicitly supplied through the single
process variable `DASHSCOPE_API_KEY`; no `.env` discovery or provider fallback
follows from preparation or a default identity check.

## Fixed batch and accounting

At most four sequential requests to the existing exact `qwen3.5-plus` transport.
The proposed aggregate soft stopping line is USD 0.05. Reserve all four calls
conservatively using the unchanged engineering policy before execution; require
four times its per-request reservation to fit that line. Do not recycle a
completed request's low estimated use into more requests. This frozen estimate
is not current retail pricing, a provider invoice or a guaranteed hard cap.
Any future grant must acknowledge possible small in-flight excess.

An exclusive fixed batch directory and durable initial claim precede key use
and possible native entry. Existing, partially written, corrupt or unresolved
outputs refuse execution, even with a new process or selector. Persist each
receipt intent before POST. No retry, redirect, repair, fallback, recovery,
search, supplementary judge or production activation is part of this protocol.

Create one one-shot accounted selector and one isolated app per case, with the
batch's shared journal/admission context. Preserve actual-thread ownership and
wait for physical completion before moving on. A new per-case ledger must not
reset aggregate limits or authorize a second attempt for an uncertain case.

Native usage, reservation consumption, rate-based cost estimate and provider
invoice status remain different facts. Unknown or partial accounting is not
zero. A failed mechanical gate, reference mismatch, refusal, unknown accounting,
model mismatch, persistence fault or exceeded/unverifiable budget stops later
cases; all remaining rows retain explicit `not_run` states.

## HTTP observation and claims allowed

Each case uses the existing isolated usage app through an in-process ASGI HTTP
client: one POST and a same-receipt GET. A lost POST acknowledgement allows only
GET observation, never another POST. Pending, unknown or unavailable recovery
stops the batch. Receipt lookup may add delivery reads; it must not add a
selector invocation, native request or paid admission. Compare saved result and
accounting separately from those code-owned delivery counters.

Check exact native request bytes/hash, reserved/finished journal coherence,
authorized model identity, reported usage, accounting publication and HTTP
binding. Accounting-only damage may still preserve a valid excerpt in the app,
but it fails this pilot's accounting gate. Save partial observations privately
without exposing provider bodies, source text or credentials in CLI diagnostics.

This is native-to-ASGI/receipt/accounting evidence, not a native real-browser
journey. Existing intercepted Chromium checks cover the renderer separately;
do not combine those observations into an unperformed browser claim.

Preserve the existing no-model keyword baseline alongside any future result.
Selection agreement with a fallible LLM reference is not source truth, general
accuracy, measured user benefit or proof of superiority to assisted search.

## Verification and release gate

Synthetic tests must exercise the HEAD-only bridge and verify that the old
validator still rejects an old packet at a new HEAD. Raw data, dependency,
review and prompt drift must fail before credentials or native output creation.
Default fresh-process tests deny keys, writes and external network calls.

Intercept the actual full HTTP request and response path; verify set-valued
references, no-fit versus refusal, exactly one dispatch per case, complete
POST/GET accounting, aggregate admission, occupied-output refusal and first-fault
stop. Inject unknown usage, journal/persistence faults, lost acknowledgements
and unsafe re-entry. Reintroducing critical defects must make unchanged tests
fail before restoring the implementation. No new skip or warning relaxation.

Run the full offline suite, current Ruff and narrow Pylint, obtain independent
review and wait for the complete CI matrix. These gates admit prepared code,
not a paid run. Production remains disconnected and zero-call shadow mode is
unchanged. Stop execution and retain the occupied artifacts on failure; deleting
a journal or changing the output path is not a recovery strategy.
